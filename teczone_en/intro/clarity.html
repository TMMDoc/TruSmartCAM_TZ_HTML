The user interface

The user interface

TecZone uses a modern user interface designed to keep the workspace focused and easy to understand. Instead of presenting every command at once, the interface shows the tools and settings that are relevant to the item currently selected.

In the TecZone interface, you will not find:

  • Many rows of stacked icons, only a few of which are relevant to the current context.

  • Deep menu structures containing dozens of commands.

  • User-interface ribbons that take up a large amount of space at the top of the screen.

Instead, the interface follows a simple principle: Select, then Operate.

  • Select an item by clicking it.

  • An interface panel opens and displays the settings and operations available for the selected item.

  • The panel may provide controls for extending the selection to other similar items.

  • The panel may also provide controls for navigating among related items.

These principles are consistent across every working mode of TecZone. Whether you are cleaning up a 3D model, arranging parts on a nested sheet, or editing press-brake tooling, you use the same core concepts.

To make these ideas concrete, the following sections demonstrate the interface using examples from the TecZone Bend report editor.

A guided tour

This is a short tour of the interface. A small number of concepts are repeated throughout TecZone, and understanding them makes most areas of the application easier to use with little additional training.

A sample report

You can learn more about creating and editing report templates in a later section. For now, the following report terminology will help illustrate the interface concepts.

The image above shows several types of entities that can be placed in a report.

  • A Label is a piece of text. You can set properties such as its font, text alignment, and color.

  • A Field displays data retrieved from the underlying Part.

  • A Shape is simple geometry, such as an ellipse, rectangle, or line, that can be used to create backdrops, highlights, or dividers in a report.

  • A Table displays tabular data retrieved from the underlying Part. In this example, the table lists the bend operations in the part and displays selected attributes for each operation.

With this background, we can now look at the interface in action.

Principle: Click an item to edit it

Click a Field, and an interface panel opens. The panel provides the controls needed to view and edit the selected item. Here is an annotated example:

Clicking a field selects it and displays a panel for editing it. The panel contains several common interface elements:

  • The caption bar can be used to reposition the panel. Click anywhere on the panel background and drag it to a new location. If you set the pushpin, panels remain anchored at that location. Otherwise, they open near the mouse cursor.

  • Edit boxes, number-input boxes, choice lists, font selectors, and alignment selectors provide different ways to view and change the field settings.

  • Action buttons perform operations on the selected item. For example, you can remove the field from the report by clicking the Delete button.

  • Panels may contain many controls. To keep them manageable, related settings are grouped into sections called Expanders. In the example above, the Visual expander is closed, while the Font expander is open. Click anywhere on an expander to open or close that section.

Principle: Select multiple items and edit them together

You can select additional entities by holding down the Shift key while clicking them. When multiple entities are selected, the panel displays the settings that can be edited for all selected items.

In the image above, three fields have been selected using the Shift+Click mechanism. The panel allows their shared settings to be edited together. In this example, the Visual expander is open and the Font expander is closed.

After changing the Bgrd. color and the Pen-wid. settings, the report looks as follows:

The changes are applied to every selected item. Notice that the Expression setting is not displayed in the multiple-edit panel. Settings that normally have different values for each item are omitted because applying one shared value would usually not be useful. For example, you would not normally want three fields to display the same value from the Part.

Principle: Edit different item types together

You can select items of different types at the same time. The panel then displays only the settings and operations that the selected items have in common.

The following example shows the panel for a Shape entity:

If you select a Field and a Shape together, the panel changes as shown below:

  • The caption bar reads 2 Report Items because the selected items are report items, even though they are different types.

  • Only settings shared by the Field and Shape are displayed. In this example, the common settings are in the Visual section.

Principle: Multiple selection can provide additional operations

Multiple selection can provide more than a common set of settings. Depending on the selected items, the panel may also display operations that are unavailable when only one item is selected.

The following example comes from the bending view. Clicking a bend opens a panel for editing its settings and performing operations on it:

The image shows the panel for bend 3. If you hold down Shift and select bend 4 as well, the panel changes:

The two selected bends share several editable settings, including whether bending is skipped and which station is used. A new Group button is also available. Because the two bends are collinear, they can be combined into a single bend operation. This additional operation is available only when the required multiple-selection conditions are met.

Clicking the Group button combines the bends, as shown below:

The part now contains three bend operations. Bend 3 is a grouped bend, so the panel provides a new Ungroup button for separating it again.

Principle: Use the Selection sub-panel to change the selection

An interface panel often includes a Selection sub-panel near the bottom. It provides commands for changing the current selection, usually by adding items that share a relevant characteristic with the selected item.

For example, the available commands might include:

  • Select all Fields in a report.

  • Select all Bend Fields.

  • Select all polylines in the current layer.

  • Select all punch hits that use the same punch tool.

  • Select all bends that use the same setup.

The following example shows a Selection sub-panel in the report editor:

The Selection sub-panel uses a distinctive patterned background and rounded buttons. In this example, the buttons can be used to select All Fields, select All Bend Fields, or Toggle the current selection.

The available selection commands depend on the current context. They are designed to make common selection tasks quick and convenient.

Principle: Use the Navigation sub-panel to move through the item hierarchy

The items in a part, report, or layout are often organized hierarchically. This structure is called the Entity Tree. It is typically represented as an upside-down tree, with a parent item at the top and its child items below it.

The following example shows an entity tree for a report:

  • A report can contain multiple items, including Tables.

  • A Table can contain multiple Columns.

The structure therefore has three levels:

This report contains two Labels, one Field, and one Table. The Table contains four columns.

When you click the table, the panel includes navigation controls for moving through this hierarchy:

The Navigation sub-panel provides directional buttons for moving through the entity tree. Like the Selection sub-panel, it has a distinctive textured background and appears near the bottom of the panel, above the Selection sub-panel.

The Prev and Next buttons move between items at the same level of the entity tree. From the table level, these buttons select other items in the report, such as the Label or Field items.

Clicking the Report button moves up from the table to its parent, the Report. The panel for the report contains settings such as the paper size and margins:

The report is the root of the entity tree, so there is no higher level to navigate to. The navigation sub-panel therefore contains only one button, Items, which moves down to the report’s item list. Clicking it selects the table again.

From the table, the Columns button moves down one level into column-editing mode. Clicking the Columns button displays the settings for the selected table column:

At the column level, the Prev and Next buttons move between the columns in the table. There is no down-navigation button because columns are the lowest level in this example. The Table button moves up one level and returns to editing the table.

Summary

  • Click an item to edit it.

  • Select multiple items to edit their shared settings together.

  • Select items of different types to edit the settings they have in common.

  • Use multiple selection to access additional operations when the selected items support them.

  • Use the Selection sub-panel to modify the current selection efficiently.

  • Use the Navigation sub-panel to move through the entity tree.
